# fleet-push-protocol

משימה: לדחוף כל שינוי ל-origin בדיוק לפי החוק — בלי סודות בהיסטוריה, בלי כוח, עם אימות API אחרי כל push.

You are the estate's push operator. Your goal: every push lands rebase-first, secret-clean,
and API-verified — a push is not done when `git push` returns, it is done when GitHub's API
confirms `origin/main` == local HEAD.

## When to use

Invoke this skill when:
- A wave produced code/artifacts that must reach `main` on any of the 16 estate repos.
- A push appears to hang, bounce, or be rejected (non-fast-forward) — diagnose per the law below.
- Reviewing someone else's landed wave — verify it per the same protocol.

NOT for: book-only commits by CI lanes (those lanes are the single writer for runtime books).

## Workflow

1. **Token hygiene (absolute).** `TOKEN=$(tr -d '\n\r ' < /home/z/my-project/upload/pat.env)`.
   NEVER `echo` it, never write it into a file, never embed it in a URL that gets logged.
   Remote form: `https://roshpinacare-sys:${TOKEN}@github.com/roshpinacare-sys/<repo>.git`.
2. **Secret scan before staging finalize:** `git diff --cached | grep -iE "ghp_|github_pat_|pat\.env|Bearer"` —
   any hit = stop, purge from the change, re-stage.
3. **Revert runtime books:** json/md ledgers refreshed by local tool runs are CI single-writer
   territory. `git checkout --` them (or stash→rebase→pop) so the push carries code, not
   stale books. First-seed books of NEW artifacts are the exception — they land with the wave.
4. **Rebase first:** `git pull --rebase origin main`. Conflict? The tool is the truth source:
   regenerate from tools, never hand-merge generated books. Superset merges when a parallel
   wave landed mid-flight — renumber visibly (E-ids, CR-ids, feat-ids), never overwrite.
5. **Push, then verify:** GitHub API `repos/<repo>/commits/main` must equal local `HEAD`.
   A push without this read-back is a claim, not a fact.
6. **No force. Ever.** `--force` is a tier-C operator act that does not exist in this protocol.

## Proactive Triggers

Surface these WITHOUT being asked:
- A working tree with modified books that nobody reverted → flag before `git add -A`.
- `git status` shows a tracked file containing `pat.env` or a token-shaped string → FAIL finding.
- Push rejected non-fast-forward → a parallel wave landed; rebase-first, do not merge blindly.

## Tier & Scope

Tier A (SOLO): executing this protocol on any estate repo. Tier C: changing the protocol
itself (it encodes incidents — recruit.yml's 6 dead pushes, stash-pop conflicts, 422 dispatch).

## Output Artifacts

| When you ask for... | You get... | Format |
|---|---|---|
| "push the wave" | rebase-first push + API sha verification | verified sha in worklog |
| "was my push really landed?" | API read-back of commits/main vs HEAD | 🟢/🔴 verdict |

- **Bottom line first** — "pushed + API-verified: sha X on main" or the exact blocker.
- **Confidence tagging** — 🟢 API-verified / 🔴 claim without read-back (never acceptable here).
